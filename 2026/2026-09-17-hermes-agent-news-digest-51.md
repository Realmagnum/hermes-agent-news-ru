## Hermes Agent v0.21.3 (v2026.9.14)

14 сентября @Teknium1 представил релиз **Hermes Agent v0.21.3** (тег `v2026.9.14`). Это корректирующий выпуск, объединяющий 338 смердженных пулл-реквестов после версии v0.21.2 в стабильный тег для downstream-окружений: Docker-образов, Hermes Cloud и хостинг-инсталляций. Основная цель релиза — оперативно доставить исправления подключения к удалённому шлюзу в инстансы Cloud, настроенные на автообновление по latest-тегу.

За отчётный период кодовая база пополнилась 1 036 коммитами (без учёта мерджей) в 2 642 изменённых файлах (+131 690 / -37 096 строк кода).

**Ключевые исправления:**
- **Устранение сброса сессий дашборда при всплесках запросов:** Оба маршрута рефреша в шлюзе (cookie-сессии и нативный bearer-роут десктопа) теперь дедуплицируют параллельные запросы с единым ротируемым refresh token. Пробуждение десктопного клиента больше не приводит к повторному использованию уже сменённого токена, что раньше вызывало ложное срабатывание механизма защиты на портале и отзыв всей сессии. Рефреш токенов вынесен из общего event loop, поэтому задержки со стороны IdP больше не подвешивают `/api/status`. На стороне портала введены скользящий 30-дневный таймаут неактивности и 5-минутный grace-период для ротированных токенов.
- **Ликвидация утечек дескрипторов записи в `state.db`:** Шлюз, дашборд и движок десктопного клиента теперь подключают ACP- и CLI-ридеры исключительно в режиме read-only, а фоновые писатели используют общий дескриптор реестра. Это сняло паразитную нагрузку дескрипторов SessionDB на хост.

**Прочие изменения под капотом:**
- Поддержка серверных JSON-RPC-запросов к клиенту и реестр Pydantic wire-контрактов с кодогенерацией TypeScript и OpenRPC для TUI-шлюза и рабочего стола.
- Настройка усилия рассуждения (reasoning effort) прямо в селекторе моделей.
- Индикатор композера и управление вспомогательными задачами в интерфейсе десктопа.
- Поддержка OpenRouter OAuth PKCE; нативное декодирование форматов HEIF, HEIC и AVIF.
- Каталоги моделей FAL пополнились Wan 3.0, Kling 3.0, Kling Image v3, MiniMax H3 Max Turbo, Gemini Omni Flash 1.1 и Meta Muse.
- Изоляция мультиплексированных профилей и запрет режима WAL для `state.db` на сетевых файловых системах.

Полный список изменений будет опубликован в масштабных release notes версии v0.22.0.

## Официальный каталог плагинов

16 сентября команда Nous Research запустила официальный **каталог плагинов Hermes Agent**. На старте в реестр вошли 4 официальных и 96 проверенных комьюнити-плагинов: от визуальной кастомизации десктопа и коннекторов к новым платформам до тулов для навигации, автоматизации и работы с моделями.

Каталог представляет собой курируемый реестр. Установка расширения выполняется одной консольной командой по его имени:

```bash
hermes plugins install <имя_плагина>
hermes plugins enable <имя_плагина>
hermes plugins list
```

В десктопном приложении каталог встроен нативно во вкладку «Обзор» (Browse) панели плагинов. Новая система работает поверх стандартного механизма плагинов, добавляя уровень верификации и простоту дискавери.

**Модель доверия и безопасности:**
- **Строгий аудит:** доступ в каталог открывается только после мерджа PR мейнтейнерами.
- **Пин конкретного коммита:** плагины привязываются к неизменяемому SHA коммита, а не к ветке. Обновление внешнего репозитория не изменит код у пользователей без отдельной верификации.
- **CI-сканирование:** при добавлении запускается тот же сканер безопасности, что и при локальной установке. Опасные маркеры блокируют публикацию автоматически.
- **Декларация привилегий:** каждый плагин обязан декларировать необходимые инструменты, хуки и переменные окружения для оценки скоупа прав перед инсталляцией.
- **Отзыв и изоляция:** удалённые из каталога плагины попадают в revocation list, и клиент блокирует их установку. Установка не означает автозапуск — плагин сначала скачивается и требует явной активации пользователем.

Сторонние Git-репозитории по-прежнему можно устанавливать напрямую по URL в обход каталога (с выводом соответствующего предупреждения о безопасности).

## Рефакторинг Hermes силами 1 393 агентов

Nous Research опубликовала отчёт о масштабном эксперименте: рефакторинге кодовой базы Hermes Agent объёмом около 1 млн строк Python силами самого агента. 2 сентября @Teknium поручил автономному агенту провести генеральную уборку репозитория.

Основная сессия длилась около 19 рабочих часов, динамически распределяя подзадачи на **1 393 субагента** (пиковая параллельность достигала 218 агентов одновременно). После перезапуска сессии и двух раундов код-ревью сообществом пулреквест был влит в основную ветку 4 сентября. 

**Архитектура и организация процесса:**
- **Оркестрация через git worktrees:** Агент-оркестратор проанализировал репозиторий, разбил его на 36 независимых доменов и сгенерировал ТЗ для воркеров. Каждый агент работал в отдельном git worktree, что исключило конфликты одновременной перезаписи файлов. Некоторые субагенты делегировали задачи глубже, выстраивая деревья до трёх уровней вложенности.
- **Инфраструктура:** Координация происходила внутри одного Python-процесса на скромном хосте с Intel Core i7 и 64 ГБ RAM. Инструменты запускались локальными подпроцессами, а инференс выполнялся удалённо через модель Claude Fable 5.1.
- **Отказоустойчивость:** Через 50 минут после старта сессия упала из-за истечения токена провайдера. Благодаря архитектуре коммиты и стейт задач сохранились: отдельная диагностическая сессия Hermes проанализировала сбой, сформировала контекст передачи и бесшовно возобновила работу.

**Результаты оптимизации:**
- Общий объём чистого Python-кода (без тестов) снизился на **34,4%** — с 1 063 826 до 698 363 строк.
- Количество файлов размером более 5 000 строк сократилось с 37 до 6. Крупнейший монолит `gateway/run.py` уменьшился с 34 847 до 5 512 строк за счёт декомпозиции на модули маршрутизации, стриминга, RPC и управления жизненным циклом.
- Число функций длиннее 300 строк упало со 192 до 2; максимальная вложенность `if/elif` снизилась с 92 до 9 ветвей благодаря табличной маршрутизации.
- Затраты на вызовы LLM составили ~$19 300 для основной сессии и ~$25 000 суммарно со всеми доработками (эквивалентная ручная работа команды сеньор-инженеров оценивается в $150 000 – $1 800 000).

Все сформированные в процессе рефакторинга архитектурные правила и паттерны были сохранены в скиллы @Teknium для дальнейшего переиспользования командой.

## Hermes Business открывается на Nous Portal

Nous Research объявила о запуске корпоративного направления: **Hermes Business** стал доступен на платформе Nous Portal. 

Организации получили возможность подключать сотрудников к единому рабочему пространству:
- **Общий биллинг:** единый баланс компании с гибкой настройкой лимитов расходов на каждого участника и инвайтами по email.
- **Каналы и мультиагентность:** развёртывание агентов под разные рабочие каналы с разграничением прав.
- **Шаринг скиллов:** создание общих корпоративных скиллов, остающихся интеллектуальной собственностью компании.

Параллельно развивается предложение **Hermes Enterprise** — изолированный самоулучшающийся стек агентов для локального развёртывания (on-premise) или запуска в частном облаке заказчика.

## Сравнение шести платформ для агентов по успешности задач

Аналитики из Composio опубликовали сравнительный бенчмарк шести агентных платформ (agent harnesses) по показателю успешности выполнения задач (task success rate).

Первую строчку разделили **Codex**, **Hermes Agent** и **Command Code** с результатом **21/29**. Следом с минимальным отрывом финишировали Claude Code (20/29), а также OpenCode и Pi Agent (по 19/29). Разрыв между лидером и аутсайдером составил всего около 7 процентных пунктов, при этом исход лишь трёх задач зависел непосредственно от выбора платформы исполнения.

Комментируя публикацию, @Teknium подчеркнул, что Hermes Agent сохраняет лидерство в индустрии по совокупности метрик: точности, себестоимости и скорости работы.

> **Источники:**
> - [@composio — Harness benchmark task success rate comparison (16 сентября 2026)](https://x.com/composio/status/2100308384247664866)

## Восемнадцать светлых тем для рабочего стола

Разработчик из комьюнити (@mykeura) представил плагин **Minimalist Themes** для Hermes Desktop. Набор ориентирован на тех, кому стандартное контрастное оформление кажется слишком резким.

Плагин интегрирует 18 тёплых светлых палитр (с названиями вроде *Beetroot Juice*, *Yuzu* и др.) прямо в системное меню настроек внешнего вида десктопного приложения. Выбранная тема привязывается к активному профилю десктопа и сохраняется между сессиями. Плагин кастомизирует только графический интерфейс десктопа и не затрагивает CLI/TUI-режимы. Для установки достаточно склонировать репозиторий в отслеживаемую директорию плагинов Hermes Desktop.

> - [@witcheer — Light warm themes for Hermes Desktop (17 сентября 2026)](https://x.com/witcheer/status/2100497828321673722)

## Скриншот прикрепляется к активной сессии
