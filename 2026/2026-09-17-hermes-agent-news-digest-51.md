# Новости Hermes Agent #51

Этот выпуск посвящён релизу v0.21.3, официальному каталогу плагинов, рефакторингу Hermes силами 1 393 субагентов, запуску Hermes Business на Nous Portal, сравнению шести платформ для агентов, 18 светлым темам для рабочего стола и прикреплению скриншота к активной сессии.

## Hermes Agent v0.21.3 (v2026.9.14)

14 сентября teknium1 опубликовал Hermes Agent v0.21.3 (тег `v2026.9.14`) — релиз исправлений, объединяющий около 338 принятых pull request'ов после v0.21.2 в стабильный тег для downstream-потребителей: Docker-образов, Hermes Cloud и размещённых развёртываний. Он нужен, чтобы исправления подключения к удалённому шлюзу дошли до агентов Cloud, которые автоматически обновляются до последнего тега.

По состоянию на контрольный коммит период с v0.21.2 включает 1 036 коммитов без учёта слияний в 2 642 изменённых файлах (+131 690 / -37 096 строк) и 338 принятых pull request'ов.

Основные изменения:

- Сессии удалённого дашборда больше не завершаются при всплесках обновления: оба пути обновления шлюза — управление через cookie и нативный bearer-маршрут рабочего стола — объединяют одновременные запросы с одним вращающимся токеном обновления. Поэтому всплеск пробуждений рабочего стола больше не может повторно использовать уже провернутый токен в механизме обнаружения повторного применения на портале и отозвать всю сессию. Обновление также вынесено из цикла событий, поэтому медленный поставщик идентификации больше не подвешивает `/api/status`. На стороне портала используется скользящий 30-дневный период бездействия и пяти-минутная льгота для провернутого токена.
- Долгоживущие процессы больше не создают утечки дублирующихся дескрипторов записи `state.db`: шлюз, движки дашборда и рабочего стола подключают ACP и CLI-читатели только для чтения, а писатели в процессе разделяют дескриптор реестра. В результате живые дескрипторы SessionDB перестают нагружать исправную топологию.

В окно релиза также вошли намеренно не описанные здесь изменения: серверные JSON-RPC-запросы к клиенту и реестр Pydantic wire-контрактов с генерацией TypeScript и OpenRPC для шлюза TUI и рабочего стола; выбор усилия рассуждения в каждом селекторе модели; значок композера и управление вспомогательными задачами в рабочем столе; OpenRouter OAuth PKCE; декодирование HEIF, HEIC и AVIF; переработка настройки одноранговых моделей Honcho; токены обновления MCP OAuth, привязанные к эмитенту; ежедневное напоминание о повторной MCP-аутентификации в рабочем столе; Wan 3.0, Kling 3.0, Kling Image v3, MiniMax H3 Max Turbo, Gemini Omni Flash 1.1 и Meta Muse в каталогах FAL; вставка таблиц Slack и API Agent Sessions; изоляция мультиплексированных профилей и исправления доступности шлюза; запрет WAL `state.db` на сетевых файловых системах. Полные примечания к этому периоду выйдут вместе с v0.22.0 и будут описывать изменения начиная с v0.21.0.

## Официальный каталог плагинов

16 сентября Nous Research объявила, что у Hermes Agent появился каталог плагинов. На старте в нём четыре официальных и 96 сообщественных плагинов для изменения рабочего стола, поддержки новых платформ, навигации, специализированных инструментов и других задач. Команда проверяет каждый сообщественный плагин и продолжит регулярно добавлять новые.

Документация описывает каталог как просматриваемый людьми реестр: плагин устанавливается по имени одной командой `hermes plugins install <имя>`. На странице каталога записи распределены по категориям — память, рабочий стол, платформы, веб и браузер, инструменты, голос, автоматизация, модели — и снабжены поиском, фильтрами уровня, метками возможностей и кнопками установки. На рабочем столе вкладка «Обзор» панели плагинов открывает нативный каталог. Он дополняет существующую систему плагинов, не заменяя её: установленные из каталога записи остаются обычными плагинами, а каталог добавляет только обнаружение и проверку.

Модель доверия основана на четырёх принципах. Доступ открывается только после принятия pull request'а мейнтейнером. Каждая запись закрепляет точный коммит, а не ветку: новая версия репозитория не меняет устанавливаемый код до отдельной проверенной смены закрепления. Приём запускает тот же сканер безопасности, что и установщик; опасный вердикт блокирует запись, а предупреждения показываются рецензенту. Запись объявляет инструменты, хуки и переменные окружения, чтобы до установки оценить область доступа. Удалённые плагины попадают в список отзыва с причиной и датой, а установщик их отклоняет. Установка не означает активацию: плагин сначала записывается на диск и должен быть включён до загрузки. Каталог обновляется не чаще чем раз в шесть часов без обновления Hermes.

17 сентября witcheer ответил на самые частые вопросы. Каталог действительно использует существующий механизм плагинов и представляет собой проверяемый список, устанавливаемый по имени. `hermes plugins enable <имя>` включает запись, а `hermes plugins list` показывает её происхождение. Сторонние репозитории по-прежнему можно устанавливать по Git URL без проверки — с предупреждением. Для публикации плагина нужен pull request с YAML-файлом в каталоге; заявитель должен владеть репозиторием, иметь релиз и зелёные проверки.

## Рефакторинг Hermes силами 1 393 агентов

15 сентября Nous Research опубликовала статью о том, как Hermes Agent очистил около миллиона строк Python в репозитории. 2 сентября Teknium поручил обычному агенту навести порядок. Основная сессия работала примерно 19 активных часов и делегировала задачи 1 393 субагентам — одновременно до 218. После перезапуска, сессии продолжения и двух раундов проверки и исправлений сообществом pull request приняли 4 сентября. Объём Python-кода без тестов сократился на 34,4%.

Оркестратор измерил код, разделил его на 36 непересекающихся групп и подготовил письменные задания на основе цели и накопленных правил, чтобы Teknium не объяснял задачу каждому работнику. Работники использовали git worktrees — отдельные копии для изменений без перезаписи файлов друг друга; некоторые делегировали части заданий дальше, образуя дерево глубиной до трёх уровней. Hermes координировал агентов в одном Python-процессе на i7 с 64 ГБ RAM, инструменты запускались локальными подпроцессами, а Claude Fable 5.1 выполнял инференс удалённо. Примерно через 50 минут истёк токен поставщика, и сбои завершили сессию, но коммиты и задания сохранились. Отдельная сессия Hermes диагностировала сбой и подготовила передачу перед продолжением. Для крупнейшего файла `gateway/run.py` работники разделили маршрутизацию сообщений, потоковую передачу, RPC и управление жизненным циклом по модулям. В других местах они объединили дублирующиеся вспомогательные функции и заменили длинные цепочки `if/elif` таблицами маршрутизации.

Сравнение показывает масштаб изменений: Python без тестов сократился с 1 063 826 до 698 363 строк; файлов длиннее 5 000 строк стало 6 вместо 37; функций длиннее 300 строк — 2 вместо 192; самая длинная цепочка `if/elif` — 9 ветвей вместо 92; `gateway/run.py` — 5 512 строк вместо 34 847. Симуляция поиска 4 000 символов в двух версиях показала снижение среднего числа возвращаемых токенов с 2 218 до 993, а поисков, требующих дополнительного окна чтения, — с 628 до 184. Расходы на модель для основной сессии оцениваются примерно в $19 300, а с последующими сессиями — около $25 000. Ручная работа оценивалась в $150 000–1,8 млн. Извлечённые уроки обновили skills Teknium, которыми можно поделиться с командой.

## Hermes Business открывается на Nous Portal

14 сентября Nous Research объявила, что Hermes Agent открыт для бизнеса. Nous Portal теперь позволяет приглашать коллег в Hermes Business: команда получает агентов на нескольких каналах, использует единый баланс с лимитами для участников и общие skills, которые становятся её собственной интеллектуальной собственностью. Hermes Enterprise предоставляет те же возможности локально или в выбранном облаке — суверенный самоусовершенствующийся стек ИИ, уже применяемый некоторыми крупнейшими компаниями мира.

В тот же день witcheer ответил на самый частый вопрос команд: как запускать Hermes для нескольких людей без отдельного счёта каждому. Схема проста: одна команда, один баланс, приглашения по электронной почте со страницы Team и лимит расходов. 17 сентября он также спросил, как люди используют Hermes на несколько человек дома или на работе: отдельный профиль для каждого на одном компьютере, шлюз для нескольких пользователей, размещённый агент каждого на командном балансе Hermes Business или другой вариант.

## Сравнение шести платформ для агентов по успешности задач

## Восемнадцать светлых тем для рабочего стола

17 сентября witcheer сообщил, что участник сообщества подготовил 18 светлых тёплых тем для Hermes Desktop для тех, кому оформление по умолчанию кажется слишком резким. Достаточно установить плагин, а затем выбрать палитру в настройках внешнего вида, как встроенную тему.

Minimalist Themes добавляет 18 тёплых светлых палитр, которые появляются в настройках внешнего вида рядом со встроенными темами Hermes. Выбранная тема Minimalist сохраняется при смене профиля рабочего стола; выбор другой темы возвращает обычное поведение отдельно для каждого профиля. Плагин влияет только на рабочий стол, но не на CLI и TUI. Установка выполняется клонированием репозитория и копированием плагина в отслеживаемый каталог рабочего стола; Hermes Desktop загружает его за несколько секунд. Если темы не появились, их можно обновить командой перезагрузки плагинов. Палитры названы в честь напитков и цветов — от Beetroot Juice до Yuzu.

> Источники: [@witcheer — a Hermes Agent community member made eighteen light, warm themes for Hermes Desktop, 17 сентября 2026](https://x.com/witcheer/status/2100497828321673722) и [mykeura/minimalist-themes-for-hermes, репозиторий GitHub](https://github.com/mykeura/minimalist-themes-for-hermes)
