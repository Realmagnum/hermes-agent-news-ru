## Автоматизация браузера: один инструмент вместо двенадцати

10 августа команда Nous Research объявила об отказе от двенадцати разрозненных браузерных инструментов Hermes в пользу единого решения на базе **Browser Use CLI 3.0**. Вместо перегруженных схем под каждый шаг и отдельных вызовов на каждый клик агент теперь просто пишет цельный скрипт под весь сценарий.

@Teknium подробно объяснил механику:
- **Оптимизация контекста:** схему сократили с восьми «тяжёлых» инструментов до одного-единственного. Агент управляет браузером через генерируемый код, а не цепочки одиночных действий.
- **Экономия ресурсов:** внутренние тесты показали снижение расхода токенов на 48–66% на задачу без потери точности выполнения.

Новый режим активируется через конфиг:
```yaml
browser.backend: browser-use
```

По словам @Teknium, механизм универсален и работает с любыми окружениями: локальным браузером, Browserbase, headless-режимом и всеми поддерживаемыми бэкендами (за исключением локального camofox). Nous Research также опубликовали ссылку на обновлённую документацию по автоматизации браузера в Hermes.

> **Источники:**

> - [@Teknium — Снижение расхода токенов до ~60% (10 августа 2026)](https://x.com/Teknium/status/2086881909209252209)

## hermes journey: таймлайн развития вашего агента

11 августа разработчик @witcheer представил новую команду CLI:
```bash
hermes journey
```

Утилита визуализирует в терминале интерактивную хронологическую шкалу всех скиллов и воспоминаний, накопленных агентом день за днём.

Команда охватывает как добавленные навыки, так и записи долговременной памяти, позволяя мгновенно понять, когда именно и в каком контексте агент приобрёл те или иные знания. В качестве примера @witcheer показал собственного агента: путь развития длиною в девять месяцев читается буквально с одного экрана.

> - [@witcheer — Демонстрация команды hermes journey (11 августа 2026)](https://x.com/witcheer/status/2087150634654896516)

## Hermes Pixel Office: визуализация агентов в VS Code

11 августа @Teknium представил забавный и практичный опенсорс-проект — **Hermes Pixel Office**. Он состоит из расширения для VS Code (доступно в Marketplace под именем `Hermes Pixel Office`) и сопутствующего плагина для Hermes Agent.

Инструмент визуализирует работу всех активных агентов в реальном времени: они отображаются в виде анимированных пиксельных персонажей в виртуальном офисе прямо в сайдбаре редактора.

@Teknium собрал проект за одну рабочую сессию и сразу выложил исходники в открытый доступ:
- Расширение для VS Code: [github.com/teknium1/hermes-pixel-office-vscode](https://github.com/teknium1/hermes-pixel-office-vscode)

## Hermes Wingtips #43: топики в Telegram или отдельный профиль

В сорок третьем выпуске серии Hermes Wingtips @witcheer разобрал актуальную проблему: как организовать работу над несколькими проектами, если используется один бот в Telegram.

На выбор есть два принципиально разных подхода:

1. **Топики (`/topic`)**: параллельные треды в рамках одного диалога с ботом. Агент остаётся прежним: всё, что он узнаёт в рамках одного проекта, обогащает его общую память и переносится на другие задачи.
2. **Отдельный профиль (`hermes profile create <имя>`)**: разворачивание независимого агента с собственным токеном бота и изолированной базой памяти.

**Рекомендация:** используйте `/topic`, если проектам полезно делить общую базу знаний и контекст, и создавайте отдельные профили через `hermes profile create`, когда между рабочими потоками нужна строгая изоляция. Оба варианта без проблем работают параллельно на одном хосте.
