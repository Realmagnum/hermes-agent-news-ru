## Hermes Desktop: установка локальных моделей в один клик

3 сентября команда Nous Research представила функцию настройки локальных моделей в один клик для приложения **Hermes Desktop**. Система автоматически сканирует аппаратные ресурсы хоста, выбирает оптимальный вес и квантование, загружает файлы и разворачивает runtime. Разработчики отдельно отметили глубокую оптимизацию под аппаратное обеспечение NVIDIA, а команда NVIDIA RTX Spark подтвердила поддержку систем на Windows и Linux.

Инженер @witcheer, активно продвигающий запуск локальных нейросетей, назвал этот релиз устранением главного барьера на пути к их массовому внедрению. Ранее развертывание требовало солидной инженерной экспертизы: точного расчета объема VRAM, подбора квантования и ручной правки флагов инференс-движка. Теперь весь процесс автоматизирован.

Согласно официальной документации:
- **Управление инференсом:** Hermes самостоятельно загружает и обновляет движок `llama.cpp`, компилируя или подбирая бинарник под конкретную архитектуру.
- **Автоматический профилинг памяти:** пользователю больше не нужно вручную подбирать размер контекста, число выгружаемых на GPU слоев (`gpu layers`) или степень сжатия весов.
- **Умная селекция:** каждый чекпоинт из каталога оценивается по трем критериям — помещается ли он целиком в VRAM, требует ли оффлоада в системную оперативную память (RAM) или превышает доступные ресурсы. Приоритет отдается варианту с максимальным качеством, который полностью помещается в видеопамять (сборки ниже 4 бит исключаются).
- **Поддержка платформ:** для Windows и Linux требуется GPU NVIDIA с поддержкой CUDA либо CPU; на macOS задействуется Apple Silicon; для видеокарт AMD используется бэкенд на базе Vulkan.

## Wingtips #62: выделенная модель для cron-задач

В 62-м выпуске серии микрогайдов Wingtips @witcheer затронул оптимизацию расходов на фоновые задачи: cron и интерактивные диалоговые сессии не обязаны делить одну и ту же LLM. По умолчанию любая новая планируемая задача наследует глобальную модель, с которой пользователь общается в чате, даже если от нее требуется всего лишь сгенерировать короткий статус-отчет.

В документации описана строгая иерархия резолвинга модели при срабатывании триггера:
1. Пиннинг модели, жестко прописанный в самой задаче.
2. Глобальный параметр `cron.model` из файла `config.yaml`.
3. Глобальная модель по умолчанию.

Опция `cron.model` позволяет один раз задать рабочую лошадку для всей cron-инфраструктуры, полностью отвязав ее от чата:

```bash
hermes config set cron.model <name>
```

После этого переключение модели в основном диалоге никак не повлияет на фоновые скрипты. При необходимости отдельной задаче можно жестко назначить не только собственную модель, но и альтернативного провайдера.

Если параметры не переопределены, Hermes фиксирует провайдера и модель на момент создания задачи. Если позже глобальный дефолт изменится, срабатывает механизм безопасного падения (**fail-closed**): задача пропускает запуск, блокирует лишние вызовы инференса и единожды отправляет предупреждение о рассинхронизации. Отключить эту защиту от дрейфа конфигурации можно командой:

```bash
hermes config set cron.model_drift_guard false
```

## Газета за ночь: автономный cron-агент для верстки утренней прессы

@witcheer обратил внимание сообщества на интересный открытый проект — репозиторий `vaelkeep/hermes-paper-agent`. Это cron-пайплайн на базе Hermes Agent, который за ночь верстает настоящую многостраничную персонализированную газету с первой полосой, тематическими колонками и нумерацией страниц.

Ключевой архитектурный принцип проекта — **LLM никогда не генерирует сухие цифры**:
- **Детерминированные данные:** погода (Open-Meteo), финансовые котировки (Yahoo Finance), шаги и домашняя бухгалтерия собираются чистыми скриптами на Python.
- **Редактура и нарратив:** агент отвечает исключительно за компиляцию текстов, подводки и форматирование.
- **Двухэтапный контроль верстки:** перед печатью запускается валидатор. Если верстка «плывет» (например, строка в таблице заняла 27 символов при лимите в 26), агент получает отчет об ошибке, точечно исправляет проблемное место и отправляет на повторный чистый проход.

Логика агента вынесена в файл `AGENTS.md` (инструкции ночного шеф-редактора) и специализированный подключаемый **скилл** Hermes. Проект распространяется под свободной лицензией MIT.
