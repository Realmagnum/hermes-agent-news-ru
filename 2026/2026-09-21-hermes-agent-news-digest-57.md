## Запуск встроенного каталога плагинов

В Hermes Agent заработал полноценный встроенный каталог плагинов. Разработчик @tonbistudio опубликовал видеодемонстрацию процесса быстрой установки на примере трех расширений: `resetwatch`, `hermes-newswire` и `hermes-office`. @Teknium подтвердил релиз: каждый плагин получил отдельную страницу с отрендеренным файлом README, сортировкой по дате добавления и фильтрацией по авторам.

На момент запуска в каталоге представлено **222 плагина** (5 официальных и 217 от сообщества), сгруппированных по 9 категориям:
- десктоп;
- память;
- платформы;
- веб и браузер;
- инструменты;
- голос;
- автоматизация;
- модели;
- общие.

Каждая карточка содержит готовую команду для установки:
```bash
hermes plugins install <название_плагина>
```
а также ссылку на исходный репозиторий, документацию, список используемых инструментов, хуков и переменных окружения.

Разработчик @witcheer раскрыл архитектуру каталога и механику проверки:
1. Плагины попадают в каталог исключительно через **пулл-реквест**, который вручную ревьюит мейнтейнер.
2. В каталоге жестко фиксируется (**пингуется**) конкретный хеш коммита.
3. Любые последующие коммиты в репозиторий автора не попадут к пользователям автоматически: команда установки загружает ровно ту ревизию, которая прошла проверку.
4. Перед установкой пользователь видит проверенную версию README, точный коммит и все заявленные права доступа (хуки, переменные, тулсеты).

## Wingtips #79: глобальное отключение тулсетов через agent.disabled_toolsets

Очередной выпуск серии Wingtips посвящен параметру конфигурации `agent.disabled_toolsets`.

По умолчанию Hermes Agent управляет наборами инструментов (toolsets) раздельно для каждой платформы: CLI, Telegram, Discord и другие клиенты хранят собственные списки, настраиваемые через `hermes tools`. Ключ `agent.disabled_toolsets` работает как глобальный фильтр наивысшего приоритета: любой указанный в нем тулсет отключается на всех платформах сразу.

Типовые примеры использования:
- Отключение тулсета `memory`: скрывает инструменты долговременной памяти и блокирует внедрение системного промпта `MEMORY_GUIDANCE`.
- Отключение тулсета `web`: гарантированно вырезает вызовы `web_search` и `web_extract` во всех интерфейсах и шлюзах.

## Оптимизация компактификации под небольшие контекстные окна локальных моделей

В кодовую базу вмерджили патч, оптимизирующий механизм компактификации (сжатия) контекста для пользователей, запускающих Hermes Agent на локальных LLM с окном от **8k до 32k токенов**.

При переполнении контекста Hermes суммаризирует старую часть диалога, оставляя самые свежие реплики нетронутыми в исходном виде. Ранее размер этого защищенного «хвоста» рассчитывался в токенах по фиксированной логике, рассчитанной на крупные облачные модели с большими окнами. 

Обновленный алгоритм адаптирует размер защищенного сегмента под реальный объем контекста: для небольших локальных сеток сохранение точного фрагмента диалога теперь оставляет достаточно свободного места для генерации ответа, предотвращая ситуации, когда агрессивная суммаризация обрывает текущую цепочку рассуждений.

## Рекордный день мерджей: 419 пулл-реквестов и вынос process providers в плагины

Разработчик @iamlukethedev отметил рекордную активность в репозитории: за один день было смерджено **419 пулл-реквестов**. Среди сотен изменений выделяются два ключевых архитектурных сдвига:

1. **Модульные process providers:** внешние провайдеры процессов теперь поставляются в виде изолированных плагинов. Сторонние провайдеры и OAuth-интеграции, находящиеся вне основного дерева исходников (out-of-tree), теперь бесшовно отображаются во всех селекторах моделей.
2. **Синхронизация голосовых настроек:** при работе в режиме бота и на десктопе движок GPT Live и синтез речи (TTS) теперь используют единые конфигурационные профили.

Архитектура Hermes Agent продолжает двигаться в сторону модульности: функционал, ранее зашитый в ядро, выносится во взаимозаменяемые плагины.

## Авторизация на сайтах по одной команде

Разработчик @witcheer подвел итоги недавних патч-релизов (v0.21.2 и v0.21.3), выделив ключевой юзкейс — бесшовную веб-авторизацию.

Теперь при выполнении Computer Use достаточно отдать агенту естественную команду вроде *«залогинься на GitHub»*. Hermes Agent самостоятельно извлечет учетные данные из подключенного менеджера паролей (**1Password**, **Bitwarden** или встроенного шифрованного хранилища Hermes) и заполнит форму входа. Функционал реализован в рамках пулл-реквестов `#106480` и `#107585`.

> **Источники:**
> - [@witcheer — Разбор возможностей релизов v0.21.2 и v0.21.3 (21 сентября 2026)](https://x.com/witcheer/status/2101982106486292787)
