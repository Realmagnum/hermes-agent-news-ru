## Ornith 1.5: нативная конфигурация для Hermes Agent из коробки

19 августа состоялся релиз **Ornith 1.5** — семейства моделей с открытыми весами (open-weight), включающего версии **9B dense**, **35B MoE** и флагманскую **397B MoE**. Главная новость для экосистемы: карточка модели (model card) уже содержит готовую конфигурацию подключения для Hermes Agent.

Как отметил @witcheer, настройка сводится к тому, чтобы направить Hermes Agent на локальный сервер с Ornith 1.5 — поддерживается любая модель линейки. 

Ключевые детали релиза:
- **Архитектура обучения:** семейство обучалось в цикле непрерывного самосовершенствования (*self-improvement loop*). Модель сама ставит себе задачи, генерирует скаффолды и формирует цепочки обучения с подкреплением (rollouts), непрерывно расширяя обучающую выборку.
- **Лицензирование:** базовые веса и квантованные версии опубликованы под свободной лицензией **MIT**.
- В ближайшее время разработчики обещают опубликовать официальные бенчмарки.

Интеграция предельно прозрачна: конфиг предоставляется в готовом виде, и агент моментально линкуется к локальному эндпоинту.

## Hermes строит интерактивные туры по своему UI и внешним сайтам

19 августа разработчик @imbabybrooklyn показал возможность Hermes генерировать динамический онбординг по собственному интерфейсу. Агент на лету выстраивает экскурсию по своим экранам и пошагово объясняет пользователю принципы работы.

Позже @witcheer раскрыл технические детали фичи: она не завязана на захардкоженные экраны самого агента. Достаточно открыть любой сторонний ресурс во встроенной панели предпросмотра (preview panel), и Hermes точно так же на лету сгенерирует интерактивный гид по странице.

В приложении нет заранее прописанных туров:
- Агент анализирует экран в реальном времени.
- Находит интерактивные контролы и элементы управления.
- Поочередно подсвечивает их с пояснениями.

Для проектов с быстро меняющимся интерфейсом это идеальный способ быстро ввести пользователя в курс дела без ручного написания документации.

## Файловые чекпоинты: быстрое восстановление удаленного проекта

19 августа @witcheer продемонстрировал механизм отката файловой системы. В демонстрационном сценарии Hermes Agent полностью удаляет рабочий каталог проекта, после чего одной командой возвращает все файлы в исходное состояние.

Логика работы механизма:
1. Перед выполнением любых деструктивных действий Hermes автоматически создает снапшот рабочей директории.
2. В случае ошибки или случайного удаления окружение мгновенно восстанавливается.

Опция является **opt-in** и активируется при запуске сессии флагом `--checkpoints`:

```bash
hermes chat --checkpoints
```

**Важное отличие:** эту функцию не следует путать с механизмом кураторского роллбэка (`/rollback`), отвечающим за снимки долгосрочной памяти. Файловые чекпоинты работают исключительно на уровне файловой системы проекта на хосте.

## Глоссарий символов CLI в официальной документации

18 августа @witcheer сообщил о добавлении нового справочного раздела в документацию — **CLI Symbols Glossary**. Страница систематизирует визуальный язык терминала Hermes, который раньше пользователям приходилось осваивать методом проб и ошибок.

Справочник объясняет значение всех служебных индикаторов:
- **Маркеры (bullets):** вызов внешнего инструмента или скилла.
- **Галочки и крестики:** статус завершения операции.
- **Шевроны:** сворачиваемые и раскрываемые блоки контекста.
- **Брайлевские спиннеры (braille spinners):** этап размышлений модели (thinking/reasoning).
- **Бейджи:** индикация вызова субагентов, голосового режима и запросов на подтверждение действий (approvals).

Теперь понять текущее состояние пайплайна можно с одного взгляда на CLI.
