## Wingtips #84: контроль параллелизма через mcp.discovery_concurrency

@witcheer посвятил 84-й выпуск заметок Wingtips новому параметру `mcp.discovery_concurrency`, который задает потолок одновременных подключений к MCP-серверам. Все объявленные в конфигурации серверы инициализируются при запуске Hermes Agent, при этом каждый локальный сервер разворачивается в отдельном системном процессе.

Обновленная документация по Model Context Protocol раскрывает технические детали:
- **Лимит параллелизма:** теперь discovery-процесс подключает не более **4 серверов одновременно** за один проход. Ограничение действует при холодном старте, вызове команды `/reload-mcp` и срабатывании watcher-демона при изменении конфига.
- **Оптимизация ресурсов:** ранее stdio-серверы порождали дочерние деревья процессов синхронно без всяких ограничений. При внушительном списке MCP это вызывало резкие скачки потребления CPU и RAM, а на мультипрофильных инсталляциях — лавину одновременных запросов к провайдерам.
- **Конфигурация:** лимит настраивается в файле `config.yaml`:
  ```yaml
  mcp:
    discovery_concurrency: 4 # по умолчанию; значение 0 отключает ограничение
  ```

## Канбан Hermes Agent переходит на двухколоночный интерфейс

Tony Simons (@tonysimons_) представил масштабный редизайн канбан-доски Hermes Agent. Это не просто визуальный рефреш, а переосмысление рабочего пространства:

- **Двухколоночный вид карточек:** комментарии, история активности, запуски и журналы воркеров теперь объединены в единую хронологическую ленту.
- **Связи и контекст:** блок зависимостей показывает реальные линкованные таски, добавлена полноценная поддержка Markdown и аккуратное отображение свойств.
- **Интерактивное управление:** как отметил @witcheer, текстовое поле для комментариев в активной задаче отправляет ввод напрямую работающему воркеру. Это позволяет корректировать выполнение и вести диалог с агентом, не покидая окно задачи.

## Генерация системного руководства силами самого Hermes Agent

@witcheer опубликовал готовый промпт, с помощью которого Hermes Agent способен составить исчерпывающую техническую документацию по собственной инсталляции.

При выполнении промпта агент опрашивает хост-систему и фиксирует:
- используемую модель и API-провайдера;
- подключенные платформы и активные cron-задачи;
- установленные скиллы и статус переменных окружения (`set` / `not set`);
- пути к базам сессий и хранилищам долговременной памяти;
- пошаговые сценарии для резервного копирования и восстановления.

Шаблон промпта доступен в реплаях к оригинальному посту автора.

## Нативное голосовое управление в Hermes OS

Разработчик @iamlukethedev продемонстрировал интеграцию нативного голосового ввода в интерфейс Hermes OS. По одной короткой голосовой команде («Создай сайт для парикмахерской») агент в режиме реального времени перешел к исполнению: написал код, переключался между окнами через механизм Computer Use и собрал работающий сайт прямо на глазах у пользователя.

Эксперимент базируется на специализированном Linux-окружении Hermes OS, над которым работает автор. Система включает кастомный рабочий стол, лаунчер приложений и изолированные воркспейсы под личные задачи, разработку и генерацию идей.
