## Wingtips #72: перенос директории для новых скиллов агента

В 72-м выпуске заметок Wingtips разработчик @witcheer разобрал механизм сохранения скиллов, которые агент пишет сам по итогам успешных сессий. По умолчанию они попадают в локальную папку скиллов текущего профиля на конкретной машине. Однако параметр `create_dir` в блоке `skills` файла `config.yaml` позволяет перенаправить сохранение — например, в общую базу знаний, репозиторий под управлением Git или сетевой том, доступный всему парку машин.

В документации подробно описано поведение этого параметра:
- **Сохранение новых навыков:** инструменты вроде `skill_manage` создают новые скиллы (включая подкатегории) внутри `create_dir`. Если папка еще не существует, она создается автоматически при первой записи.
- **Динамические инструкции:** системный промпт не перегружается лишними инструкциями — агент автоматически получает актуальные пути в описании тулов.
- **Бесшовная интеграция:** папка полностью объединяется с локальным хранилищем. Скиллы сканируются вместе, отображаются в общем индексе, командах `skills_list`, `skill_view`, слэш-командах, а также доступны для редактирования и удаления.
- **Что остается без изменений:** существующие скиллы продолжают редактироваться на своих исходных местах, а синхронизация коробочных скиллов, хаб и куратор по-прежнему работают с локальной папкой профиля.

Пути поддерживают раскрытие тильды `~` и переменных окружения, а относительные пути разрешаются относительно корневой директории Hermes. Если оставить `create_dir` указывающим на локальную папку, поведение останется стандартным.

## Тестирование промптов на копии агента

@witcheer поделился полезной практикой: каждый промпт из серии *Hermes Autopilot* и каждая команда из выпусков Wingtips перед публикацией прогоняются на изолированной копии агента, а не на основном рабочем профиле. 

Создать такую тестовую песочницу можно буквально одной командой:

```bash
hermes profile create test --clone
```

Флаги клонирования профилей из справочника CLI:
- `--clone` — копирует из активного профиля конфигурацию, файл переменных `.env`, `SOUL.md`, пользовательские скиллы и курируемую память (`MEMORY.md` и `USER.md`).
- `--clone-all` — полностью переносит абсолютно все состояние и историю профиля.
- `--clone-from <source>` — задает конкретный исходный профиль (по умолчанию клонирует только конфигурацию, если не указан `--clone-all`).

## Настройка вспомогательных моделей от Teknium

@Teknium ответил на частый вопрос сообщества и показал, как устроена конфигурация вспомогательных (auxiliary) моделей в его инсталляции: связка с Gemini Flash существенно снижает затраты на рутинные вызовы, а модель Astra привлекается как независимый ревьюер при вызове `/review`.

По умолчанию Hermes Agent не требует дополнительной настройки, но при использовании тяжелых reasoning-моделей служебные операции могут заметно раздувать бюджет. Вынесение фоновых задач на быстрые и дешевые модели решает эту проблему. 

Вспомогательные модели можно настроить для целого спектра задач:
- Компьютерное зрение (vision);
- Генерация заголовков и аудиотегов;
- Сжатие контекста;
- Классификатор подтверждений и триаж-роутер;
- Декомпозитор канбан-задач;
- Генератор описаний профилей и делегирование.

Для каждой роли задаются провайдер, модель и при необходимости кастомный OpenAI-совместимый эндпоинт. Команда `/review` запускает изолированного субагента-ревьюера с аналогичными правами, который анализирует контекст последних 10 сообщений. Задать для него отдельную модель можно ключом `auxiliary.review` в `config.yaml` (по умолчанию используется основная модель агента).

## Селектор усилия рассуждения в десктопном композере

В композере десктопного приложения появился отдельный селектор для настройки глубины рассуждений (reasoning effort).

Элемент управления расположен слева от иконки микрофона. Для каждой модели доступны опции включения рассуждений, уровня усилий и быстрого режима (fast mode). Бейдж с текущим уровнем (`Med` или `High`) позволяет менять параметры в один клик без необходимости открывать полный список моделей. Для моделей, не поддерживающих настройку рассуждений, бейдж скрывается. Приложение запоминает выбранные настройки для каждой модели и применяет их при переключении сессий (на cron-задачи и субагентов эти параметры не влияют).

**Обнаруженный сайд-эффект:**  
В ишью `#107949` описана проблема: композер инициализирует значение усилия из глобального параметра `agent.reasoning_effort` и передает его при создании каждой сессии. Из-за этого точечные переопределения в `agent.reasoning_overrides` игнорируются. Например, при связке глобального `agent.reasoning_effort: high` и правила `gpt-5.6-sol: none` запрос все равно отправлялся с флагом `high`. Если эндпоинт запрещает одновременный вызов тулов и рассуждений, это приводило к ошибке 400 Bad Request. В прикрепленном пулл-реквесте предложено не передавать параметр принудительно, если он совпадает со значением по умолчанию, что сохранит работу индивидуальных оверрайдов.

## GPT Image 2.5 на Nous Portal

@Teknium сообщил о добавлении модели ChatGPT-Image-2.5 на платформу Nous Portal. Теперь к ней можно обращаться внутри Hermes Agent наряду с уже поддерживаемыми прямыми интеграциями через FAL и OpenAI.

Модели линейки разделены под задачи:
- **GPT Image 2.5 Flare** — быстрая генерация изображений на каждый день;
- **GPT Image 2.5 Sunburst** — высокоточная генерация и детальное редактирование.

Обе версии поддерживают передачу до 16 референсных изображений. Уровень качества по умолчанию выбирается автоматически, но его можно зафиксировать вручную суффиксами `-low`, `-medium`, `-high`, `-xhigh` или `-max`. Для маршрутизации через FAL используются идентификаторы вроде `openai/gpt-image-2.5/flare/text-to-image` или аналогичный для Sunburst. 

Разработчики напоминают: доступность через шлюз Nous Portal регламентируется белым списком разрешенных эндпоинтов, поэтому ошибки HTTP 4xx говорят о том, что конкретная модель пока не проксируется порталом.
