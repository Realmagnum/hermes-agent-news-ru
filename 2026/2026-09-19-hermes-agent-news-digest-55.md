## Wingtips #77: звуковые сигналы завершения задачи и приглашения

77-й выпуск Wingtips посвящён `display.bell_on_complete` и `display.bell_on_prompt` — двум настройкам CLI Hermes Agent, рассчитанным на работу в фоне. Пользователь запускает в CLI долгую задачу и отходит: за это время агент либо завершает работу, либо останавливается, чтобы задать вопрос, запросить подтверждение, пароль sudo или получить секрет.

Страница конфигурации подробно описывает оба логических ключа. `display.bell_on_complete` проигрывает сигнал терминала после завершения агентом работы — это удобно для долгих задач. `display.bell_on_prompt` проигрывает сигнал при появлении блокирующего приглашения: clarification, approval, запрос пароля sudo или получение секрета; настройка работает и по SSH. Оба флага дополнительно отправляют desktop-уведомление OSC 9, которое Ghostty, iTerm2, Kitty и WezTerm показывают как системное оповещение. В Warp с объявленным протоколом CLI-agent также создаётся событие `warp://cli-agent` OSC 777: сигнал `stop` после завершения задачи и `permission_request` при блокирующем приглашении. Благодаря этому вкладка и очередь уведомлений Warp следят за Hermes без дополнительного ключа.

## Маршрутизация профилей по отправителю вошла в gateway

19 сентября weiszfeld объявил, что маршрутизация профилей по отправителю вошла в upstream-репозиторий NousResearch. Вкладка стала возможной благодаря реализации Italo Fernandes и port Teknium; автор планирует сделать это первым из многих вкладов в Hermes, разрабатываемых с помощью самого Hermes.

Pull request #106019 подробно описывает механизм. `gateway.profile_routes` раньше мог различать только источник сообщения, `guild_id`, `chat_id` или `thread_id`. Поэтому для двух людей в одном канале, которым нужны отдельные изолированные профили, приходилось запускать двух ботов. Исправление добавляет `user_id` — четвёртый критерий, содержащий отправителя входящего сообщения. Он сравнивается точным совпадением вместе с полями расположения, поэтому комбинация `user_id` и `chat_id` обозначает конкретного человека в конкретном канале. Автор отказался от отдельного механизма, предложенного в issue #33548: достаточно необязательного поля в существующей записи маршрута, без новой поверхности конфигурации:

```
gateway:
  multiplex_profiles: true
  profile_routes:
    - name: teams-owner
      platform: teams
      user_id: "00000000-0000-0000-0000-000000000000"
      profile: owner
```

Задачи cron намеренно исключены: у запланированной задачи нет аутентифицированного входящего отправителя, поэтому маршрут по `user_id` не должен случайно разрешить доставку общей задаче бота. Документ теперь явно фиксирует это ограничение. Production diff содержит 45 добавлений и 21 удаление в восьми файлах. Добавленные тесты проверяют, в частности, разделение трёх отправителей общего канала по трём профилям, а также точное сравнение идентификатора — с учётом регистра и в сочетании с `chat_id`.

> Источники: [@weiszfeld — Sender-based profile routing just landed upstream, 19 сентября 2026](https://x.com/weiszfeld/status/2101217377387974657) и [PR #106019 — feat(gateway): route inbound messages to profiles by sender user_id, репозиторий hermes-agent, 8 сентября 2026](https://github.com/NousResearch/hermes-agent/pull/106019)

## Hermes-Portal: read-only витрина установки

19 сентября witcheer рассказал о созданной участником сообщества rpmalouin read-only веб-странице для всего, что хранит установка Hermes: skills и места их размещения, прошлые разговоры с поиском, cron scheduler, стоимость каждой сессии, память, плагины и состояние системы, читаемые непосредственно из файлов и баз данных.

GitHub-репозиторий страницы называется Hermes-Portal. Он публичный, распространяется под лицензией MIT и на момент проверки имел 53 звезды. Сначала проект назывался Hermes-Dashboard, но 17 сентября получил новое имя, чтобы его не принимали за второй dashboard рядом с тем, который Hermes уже разворачивает на порту 9119. В проекте 518 тестов. Проверка drift, повышенная до CI-задачи на каждый push, монтирует копии установки Hermes и намеренно ломает каждую так, как её может сломать обновление: переименовывает колонку, меняет формат cron-хранилища, подставляет случайные байты вместо состояния. Затем она проверяет, что отображение остаётся рабочим и затронутыми помечаются только действительно изменившиеся элементы. Именно эта проверка нашла последние три бага. Демонстрационный скриншот создаётся из поставляемого в репозитории capture-устройства, поэтому его можно воспроизвести четырьмя командами.

> Источники: [@witcheer — a Hermes Agent community member built a read-only web page for everything a Hermes install keeps, 19 сентября 2026](https://x.com/witcheer/status/2101279655281955219) и [Hermes-Portal — репозиторий GitHub rpmalouin, лицензия MIT](https://github.com/rpmalouin/Hermes-Portal)
