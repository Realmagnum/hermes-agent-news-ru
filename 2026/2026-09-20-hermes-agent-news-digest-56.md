# Новости Hermes Agent #56

Этот выпуск возвращается к семидесятому восьмому номеру Wingtips, посвящённому настраиваемой политике интеллектуальных одобрений, контекстному движку для длинных бесед, настройке длины ответов на лету и новому элементу управления отображением в настольном приложении. В заключение рассматривается ответ Hermes на сравнение по компрессии между сторонней моделью и её внутренней реализацией. С момента выпуска v0.21.3 от 14 сентября новых релизов не публиковалось.

## Wingtips #78: approvals.smart_policy

Семьдесят восьмой номер Wingtips посвящён `approvals.smart_policy` — ключе, расширяющей режим интеллектуального одобрения Hermes Agent. Когда агент хочет выполнить потенциально опасную терминальную команду, второй модель предварительно проверяет её, читает команду и отвечает одним словом: одобрить, отклонить или поднять (то есть запросить у вас). Эта ключ позволяет добавить собственные правила в эту проверку.

Страница конфигурации описывает механизм. В режиме `smart` помощник-модель (guardian LLM) оценивает, действительно ли отмеченная команда опасна: команды низкого риска одобряются автоматически только для этого выполнения, действительно опасные команды отклоняются, а неопределённые решения передаются пользователю. `approvals.smart_policy` добавляет ваши собственные правила в инструкции этого эксперта; текст вставляется в системное сообщение модели-хранителя через доверенный канал, никогда не рядом с ненадёжным текстом команды. Таким образом можно усилить или ослабить её judgement в зависимости от окружения, не пишая код, например, всегда поднимать любую команду, модифицирующую что-то в `/etc`, или заранее одобрять перезапуски Docker из папки развёртывания.

## Движок контекста для длинных бесед

witcheer relayed 20 сентября плагин, созданный членом сообщества — движок контекста, предназначенный для длинных бесед. Плагин сохраняет каждое сообщение сессии в локальное хранилище SQLite, сворачивает самые старые раунды в многослойные суммары и строит промпт на лету из этих суммаров, дополненных последними сообщениями.

Архив первична: ничего не теряется, всё записывается в локальную базу. Окно остаётся читаемым, потому что старое сжимается, а живое контекст восстанавливается каждый раунд из суммаров и конца сессии, вместо фиксированного окна, которое резко отбрасывает выходящее за пределы.

> Источники: [@witcheer, участник сообщества Hermes Agent создал плагин движка контекста для длинных бесед, 20 сентября 2026](https://x.com/witcheer/status/2101634750473498915)

## Длина ответов регулируется одной командой

tonbistudio показал 20 сентября, как настроить длину ответов агента одной терминальной командой: `hermes config set agent.text_verbosity low/medium/high`. Установка `low` даёт краткие ответы, `medium` — средний уровень. Настройка относится к секции `agent` конфигурации.

Страница конфигурации уточняет область применения réglages. `agent.text_verbosity` — независимая от глубины рассуждения ключ, применяющаяся только к моделям семейства Responses (GPT-5 OpenAI и последующие, напрямую через OpenAI, Codex ChatGPT и Azure). Hermes передаёт её как поле `text: {verbosity: ...}` в начале запроса, исключительно на эти маршруты; ключ никогда не отправляется в `chat_completions`, ни в запросы Anthropic или xAI, и пустое значение не возвращает провайдеру ничего дополнительного.

В духе настройки через CLI witcheer напомнил в тот же день привычку мониторинга: перед написанием любой строки о настройке Hermes Agent следует спросить саму установку через `hermes config get approvals.mode`, которая покажет фактически выполняемое значение, будь то значение по умолчанию или нет, без необходимости копаться в `config.yaml`.

## Скрытие блоков diff в настольном приложении

Продукт представил 20 сентября новый элемент управления отображением в настольном приложении Hermes Agent: теперь можно скрывать большие блоки diff кода в настройках, во вкладке Внешний вид. Запрос поступил от человека, близкого к команде, и возможность сворачивать эти блоки ранее не рассматривалась.

Сообщение призывает сообщество предлагать другие элементы интерфейса для скрытия. Настройка присоединяется к переключателям отображения приложения, направленным на облегчение чтения, когда участки кода становятся второстепенными.

> Источники: [@imbabybrooklyn, Теперь можно скрывать большие блоки diff кода в Настройки→Внешний вид, 20 сентября 2026](https://x.com/imbabybrooklyn/status/2101496611218104331)

## Компактизация: Hermes отвечает на сравнение с Jev

Распространялось сравнение по поводу компактизации — техники, с помощью которой агент сокращает разросшуюся беседу. 19 сентября Teknium ответил на утверждение, что Jev, сторонняя модель, сделает компактизацию быстрее и лучше, приведя факты из воспроизводимой оценки. По его мнению, компактизация Jev страдает от нескольких проблем; главная заключается в том, что, применённая к публичной оценке компактизации Hermes (которую может выполнить каждый), она приводит к программному правилу, которому не нужны ни Jev, ни любая другая модель.

iamlukethedev резюмировал численный результат теста, проведённого на Hermes с той же оценкой. Продакшн-компактизация Hermes достигает 78,9% полноты при 55 000 токенов, против 75,5% у Jev. Эти цифры и критические замечания исходят от создателя Hermes и участника сообщества относительно стороннего продукта, метод которого не прошёл независимую проверку.
