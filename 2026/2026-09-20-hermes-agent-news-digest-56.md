## Wingtips #78: approvals.smart_policy

Вышел 78-й выпуск серии Wingtips, посвященный параметру `approvals.smart_policy`. Эта опция расширяет возможности режима «умных подтверждений» (Smart Approvals) в Hermes Agent. 

Когда агент собирается выполнить потенциально опасную терминальную команду, в игру вступает вспомогательная модель-валидатор (guardian LLM). Она анализирует запрос и выносит один из трех вердиктов: выполнить автоматически, заблокировать или эскалировать решение пользователю.

Ключ `approvals.smart_policy` позволяет передать валидатору кастомные правила:
- **Безопасная доставка инструкций:** Пользовательские политики подмешиваются непосредственно в системный промпт guardian LLM через доверенный канал, полностью исключая смешивание с недоверенным кодом самой команды.
- **Гибкость без лишнего кода:** Можно точечно ужесточать или смягчать политики безопасности в зависимости от окружения. Например, требовать обязательного ручного аппрува для любых правок в `/etc` или автоматически разрешать перезапуск Docker-контейнеров (`docker restart`) в директории деплоя.

## Кастомный движок контекста для долгих сессий

@witcheer обратил внимание на плагин, разработанный участником сообщества: специализированный движок контекста для длительных диалогов.

Архитектура решения построена на следующих принципах:
- **Надежное локальное хранилище:** Каждое сообщение сессии персистентно сохраняется в локальной базе данных SQLite.
- **Многоуровневое сжатие:** Старые витки диалога (turns) агрегируются в иерархические саммари.
- **Динамический контекст:** Рабочий промпт собирается на лету из актуальных саммари и последних сообщений сессии. 

Такой подход защищает от потери важной информации и избавляет от проблем жесткого скользящего окна контекста, при котором старые данные попросту отсекаются.

## Управление длиной ответов одной командой

Разработчик @tonbistudio напомнил, как на лету регулировать подробность ответов агента прямо из терминала:

```bash
hermes config set agent.text_verbosity low # варианты: low, medium, high
```

Значение `low` делает ответы максимально сжатыми, а `medium` задает сбалансированный уровень детализации. 

**Важные нюансы работы флага:**
- Параметр не связан с глубиной рассуждений (reasoning effort).
- Опция поддерживается только семейством моделей с API Responses (линейка OpenAI GPT-5 и новее: прямой API OpenAI, Codex ChatGPT и Azure).
- Значение передается в объекте `text: {verbosity: ...}` в начале запроса. Для эндпоинтов `chat_completions`, а также провайдеров Anthropic и xAI этот ключ игнорируется.

Параллельно @witcheer поделился полезным лайфхаком: вместо проверки файлов `config.yaml` вручную статус конкретной настройки в рантайме всегда можно быстро узнать через CLI:

```bash
hermes config get approvals.mode
```

## Скрытие блоков диффов в десктопном приложении

В десктопном клиенте Hermes Agent появилась новая опция кастомизации интерфейса: теперь громоздкие блоки с разницей в коде (diffs) можно скрывать. Настройка находится в меню **Settings → Appearance**.

Возможность сворачивания диффов призвана разгрузить визуальное пространство и упростить чтение диалога, когда детальный просмотр изменений кода не требуется. Команда также открыта к предложениям сообщества по добавлению тумблеров для других элементов интерфейса.

> **Источники:**
> - [@imbabybrooklyn — You can now hide the big code diffs blocks in Settings→Appearance (20 сентября 2026)](https://x.com/imbabybrooklyn/status/2101496611218104331)

## Компакция контекста: Hermes против стороннего решения Jev

В сообществе разгорелась дискуссия вокруг механизмов компакции (сжатия разрастающегося контекста агента). В ответ на заявления о том, что сторонняя модель Jev сжимает контекст качественнее и быстрее, основатель проекта @Teknium опубликовал результаты открытого бенчмарка.

Основные тезисы:
- Анализ показал, что реализация сжатия в Jev сводится к программным эвристикам, для выполнения которых отдельная нейросетевая модель попросту не требуется.
- Разработчик @iamlukethedev привел результаты воспроизводимого тестирования: на объеме в 55 000 токенов продакшн-механизм компакции Hermes демонстрирует полноту восстановления контекста (**recall**) на уровне **78,9%**, тогда как решение на базе Jev достигает лишь **75,5%**.
