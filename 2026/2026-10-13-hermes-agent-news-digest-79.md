## 81 пулл-реквест смерджен 12 октября

iamlukethedev подвёл итоги 13 октября: 12 октября в Hermes смерджили 81 пулл-реквест. Среди заметных изменений:

- В Desktop вернулись предпросмотры сессий рядом с чатом; они обновляются, даже когда окно работает в фоне.
- Остановка теперь всегда завершает текущий ход. Desktop позволяет удалить любую сессию, а все сценарии возобновления восстанавливают сохранённое рабочее пространство именованного профиля.
- Ключи Anthropic Console (`sk-ant-usr`, `sk-ant-svc`, `sk-ant-admin` и `key_cmd`) теперь проходят аутентификацию через `x-api-key`, а не Bearer или OAuth.
- Langfuse вынесли из ядра в официальный плагин `langfuse`; для существующих пользователей предусмотрена автоматическая миграция.
- `plugins validate` предупреждает, если плагин импортирует внутренние модули Hermes.
- API жизненного цикла субагентов маршрутизирует провайдера при каждом запуске и работает в изолированной среде хоста.
- `Ctrl+C` очищает набираемый черновик, не завершая выполняющийся ход.
- Плагины можно устанавливать с любого зеркала пакетов: Hermes проверяет, что релиз не старше трёх дней, при фиксации версии, а не на компьютерах пользователей.
- Home Assistant больше не устанавливается автоматически в профилях, где им никогда не пользовались; неудачные автоустановки плагинов откладываются, а не повторяются каждый час.
- При первом использовании коннектора отображается гостевая идентичность, а коннекторы бесплатного уровня используют отдельный гостевой токен.
- После прогрева фиксированный префикс промпта сокращает каждый запрос на 2,1 тыс. токенов.
- Проверка продвижения стабильного релиза теперь опирается на подтверждения загрузки вместо повторного скачивания примерно 33 ГБ. Установка только ядра, включая `hermes update`, снова работает через зеркала без временных меток загрузки.

Всего вошли 81 новая функция и исправление.

## redline — плагин для ревью в Desktop

13 октября witcheer рассказал о созданном сообществом `redline` — плагине Hermes Desktop для ревью документов и кода, которые пишет агент.

- Файл открывается в панели рядом с чатом. Можно выделить фрагмент и оставить комментарий, вопрос или запрос на правку.
- Заметку можно отправить сразу или собрать несколько и отправить одним пакетом.
- Агент редактирует документ, а панель обновляется; заметки сохраняются рядом с файлом.

Плагин доступен в каталоге, поддерживается silentpr0, закреплён на версии `0.1.0` и требует Hermes `0.21.5` или новее. По описанию каталога, он читает выбранный пользователем локальный файл `.md` или `.markdown` размером до 1 МБ (с разрешением символических ссылок), а записывает только соседний файл `<документ>.md.redline.json`. Хук `transform_llm_output` добавляет директиву `::redline` к подходящим финальным ответам.

Плагин не использует сеть за пределами локального шлюза, учётные данные, телеметрию или дочерние процессы. Пока панель открыта, она опрашивает локальный бэкенд раз в три секунды.

```bash
hermes plugins install redline
```

## The Verge ведёт дневник использования локального ИИ с Hermes Agent

witcheer поделился 12 октября статьёй The Verge: журналист Antonio G. Di Benedetto начал вести дневник использования локального ИИ. Он установил Hermes Agent на Mac Studio M5 Ultra с 256 ГБ объединённой памяти. Выбранная модель Qwen 3.8 Flash Next насчитывает 125 млрд параметров и занимает около 105 ГБ; управляет агентом автор с телефона через Telegram-бота.

В дневнике описаны первые практические задачи:

- Запланированный cron-брифинг читает почту и календарь и добавляет прогноз погоды. Несколько запусков в 7:30 сорвались, потому что Mac спал.
- Для сортировки библиотеки Steam — более 400 игр — потребовался ключ Steam Web API. Автор удалил его сразу после выполнения задачи.
- Hermes также анализировал финансовые выписки и готовил сравнительную таблицу характеристик ноутбука до снятия эмбарго.

Главная мотивация — приватность: обрабатывать на собственном компьютере данные, которые не хочется отправлять в облако. Вывод автора сдержанный: локальный ИИ — это программа, за которой нужно следить, а не цифровой друг.

## Файлы контекста: пять ответов

13 октября witcheer опубликовал пять ответов о файлах контекста Hermes Agent:

- **Что загружается?** Инструкции проекта хранятся в `.hermes.md` или `AGENTS.md`; также читаются файлы, используемые другими инструментами для кодинга. `SOUL.md` — отдельно: он находится в `~/.hermes` и задаёт личность и тон агента.
- **Какой файл приоритетнее?** За одну сессию загружается только один тип проектного файла — первый совпавший в порядке `.hermes.md`, затем `AGENTS.md`, затем файлы других инструментов. `SOUL.md` вне этой очереди и загружается в каждой сессии.
- **Где их искать?** В рабочем каталоге. В CLI это папка, откуда запущен `hermes`; в мессенджерах — `terminal.cwd` в конфигурации, а если он не задан, домашняя папка.
- **Что с вложенными каталогами?** В Git-репозитории загружаются все `AGENTS.md` от корня до рабочего каталога; более глубокие файлы имеют приоритет. При работе в других подпапках их контекстные файлы подхватываются при первом обращении.
- **Как проверить, что загружено?** Команда `/context` выводит список файлов контекста, отмечая загруженные и пропущенные из-за более приоритетного файла. Команда выполняется локально и не обращается к модели.

Документация уточняет механику: `AGENTS.md` Git-репозитория объединяются в цепочку при запуске, а файлы подпапок добавляются по мере того, как агент впервые обращается к ним. `SOUL.md` загружается только из `HERMES_HOME`, но не из рабочего каталога.
