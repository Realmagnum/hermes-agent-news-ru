## Установка плагинов Hermes из приватных репозиториев

@Teknium объявил о поддержке установки плагинов Hermes Agent из приватных репозиториев с использованием уже сохраненных учетных данных.

Команда установки выполняется в неинтерактивном режиме и не запрашивает логин или пароль вручную:
```bash
hermes plugins install <url>
```

Для приватных `https://`-репозиториев поиск токенов авторизации происходит по цепочке:
1. Переменные `GITHUB_TOKEN` или `GH_TOKEN` из файла `.env` (только для GitHub).
2. Сессия официального CLI GitHub (`gh auth login`, только для GitHub).
3. Системный хелпер учетных данных (`git credential fill`) для указанного хоста — этот вариант обеспечивает прозрачную работу с GitLab, Bitbucket и self-hosted инстансами.

Токен передается исключительно в виде одноразового HTTP-заголовка на время установки или обновления и **никогда не сохраняется** в локальном `.git/config` плагина. Этот же механизм резолвинга учетных данных распространяется на `hermes plugins update`, установку MCP-серверов из git и загрузку профилей по git-ссылкам.

## oh-my-hermes: комьюнити-слой управления поверх Hermes

@witcheer обратил внимание на проект `rlaope/oh-my-hermes` — надстройку над Hermes Agent от участника комьюнити, которая управляет параметрами каждого запуска: определяет модель и уровень reasoning/effort под конкретную задачу, подгружает нужные скиллы и задает критерии готовности (Definition of Done).

Ключевые особенности проекта:
- **Контроль памяти:** новые записи попадают в карточки ревью, где пользователь может подтвердить, отклонить или отложить сохранение факта с указанием причины. Каждая подтвержденная запись сохраняет источник и дату ревью, при этом штатный механизм памяти Hermes остается нетронутым.
- **Архитектура:** позиционируется как единый плагин, включающий инструменты ассистирования коду, долговременную память и пресеты воркфлоу, оптимизированные под разные модели. Слой декомпозирует задачу, выстраивает пайплайн валидации и вызывает нативные скиллы как атомарные функции в рамках заданного сценария, не подменяя сам рантайм Hermes.
- **Статус проекта:** на момент релиза v2.0.2 репозиторий насчитывает около 1600 звезд, 140 форков и 22 контрибьютора (лицензия MIT).

## Wingtips #68: вызов скиллов через слэш-команды

В 68-м выпуске заметок Wingtips @witcheer разобрал частую проблему: скилл установлен, пользователь просит агента применить его в диалоге, но модель выдает стандартный ответ без изменений.

Решение заключается в том, что каждый установленный скилл автоматически регистрируется как **слэш-команда**:
- Команда с аргументом (например, `/humanizer перепиши этот ответ от моего лица`) принудительно активирует скилл на текущий шаг диалога и передает ему последующий текст как инструкцию.
- Вызов команды без аргументов просто подгружает скилл в контекст, после чего агент сам уточнит необходимые параметры.
- В одном сообщении можно объединять до пяти скиллов подряд в начале строки — все они активируются одновременно, а остальной текст станет промптом:
  ```bash
  /skill-a /skill-b обработай эти данные
  ```
- Парсер останавливается на первом токене, не являющемся зарегистрированным скиллом.

Чтобы агент выбирал скилл автоматически без явного ввода слэш-команды, описание скилла должно начинаться непосредственно с **условий применения** (триггеров), а не с общего контекста или предыстории инструмента.

## Контекстные подсказки в интерфейсе Hermes Desktop

В десктопном клиенте Hermes Desktop появились встроенные контекстные подсказки, разработанные Brooklyn в ответ на запрос сообщества подсказывать функции прямо внутри интерфейса в момент их актуальности.

Возможности механизма:
- **Интерактивные тултипы:** во время ответа агент может подсветить конкретный UI-элемент всплывающей подсказкой (например, сразу после генерации нового плагина без дополнительных запросов со стороны пользователя).
- **Фоновые подсказки:** приложение периодически демонстрирует ненавязчивые советы по работе с интерфейсом только в моменты простоя (idle).

Работу механики Brooklyn продемонстрировала на примере создания плагина онлайн-радио на базе nightride.fm: сразу после завершения сборки Hermes сам сфокусировал внимание пользователя на новом компоненте через встроенную подсказку.

## Практические замеры шести флагов llama-server

@witcheer провел детальный бенчмарк шести спорных флагов `llama-server`. Тестирование проходило на видеокарте RTX 5090 с контекстом в 16 000 токенов на шести моделях: Qwen3.8-27B, Gemma 4 31B, Qwen3.6-35B-A3B, Nemotron Lightning, Ornith 35B и Qwopus Flash.

Результаты замеров:
- `--flash-attn on`: не дает изменений, так как режим `auto` включает FlashAttention по умолчанию.
- `--parallel 1`: не требует накладных расходов, высвобождает 2,3 ГБ VRAM и увеличивает скорость глубокого декодинга на 10% (протестировано на Gemma).
- **Квантование KV-кэша в q8:** снижает потребление памяти (от 1 до 2,6 ГБ) только на плотных (dense) моделях. На архитектурах MoE с 3 млрд активных параметров экономит всего 0,1 ГБ ценой падения скорости декодинга на 5–7%.
- **Квантование KV-кэша в q4:** вызывает серьезную просадку производительности — скорость декодинга падает на 17%, 23%, 27%, 23%, 29% и 17% соответственно на контексте в 16k во всех шести моделях. При этом качество ответов по бенчмарку GPQA практически не страдает (для Ornith показатели в f16, q8 и q4 составили 100, 100 и 98).
- **MTP (Multi-Token Prediction / спекулятивное декодирование):** дает ускорение в 2,2× на Qwen3.8 (со встроенной головой) и в 1,5× на Gemma (с комьюнити-головой), но замедляет генерацию до 0,7× на Lightning. При базовой скорости выше 300 токенов/с фаза верификации тратит больше времени, чем экономит генерация драфта.
- **Время до первого токена (TTFT):** на холодном промпте в 16k токенов составляет 5–6 секунд, при попадании в кэш — 0,1–0,4 секунды.
